# REA 管理器

逆向分析环境安装器 + 在场开关。**双击一次，环境和技能全部自动就位，不需要你手动导入任何东西。**

---

## 一、安装（只做一次）

> **首选：直接让 Agent 装。** 把本仓库的 ZIP 下载或发给 AI 助手，说一句"安装这个 REA 管理器"，它会完整解压、探测 Python、跑完安装并汇报汇总。你不用手动导入任何东西。
>
> 没有 Python 也没关系：安装器会自动下载官方便携版 3.12.10（10.6 MB，解压即用，不需要管理员权限）。

**Agent 安装时按这个顺序做**（`SKILL.md` 里也有同样说明）：

1. 完整解压 ZIP 到任意目录（不要在压缩包里直接执行）。
2. 探测系统 Python（`py -3` 或 `python`，需 3.10+）；探测不到就跑 `rea\scripts\bootstrap-python.ps1` 下载便携版。
3. 用探测到的 Python 跑 `rea\scripts\install_all.py`，等它跑完。
4. 汇报汇总：Node/JDK/REA CLI 必须为"完成"；IDA 显示"跳过"是正常的（本体需自备）。
5. 提醒你重启客户端。

**手动安装（备选）**：完整解压后双击 `rea\install-windows.cmd`，其余步骤全自动。

无论哪种方式，看到汇总里没有红色"失败"就行。**装完重启 WorkBuddy（或你用的客户端）**——技能列表要重启才会刷新。

## 无法自动的三件事（这些必须你来做）

安装器会明确提示，提前列在这里：

| # | 事项 | 为什么不能自动 | 你要做的 |
|---|---|---|---|
| 1 | **安装 IDA Pro 本体** | 商业软件，需要许可证，安装器只负责"接入"不负责"安装" | 从 hex-rays.com 购买/安装并激活；装好后跑 `/rea install`，它会自动探测到 |
| 2 | **重启客户端** | 技能列表和 MCP 注册只在启动时加载 | 装完后重启 WorkBuddy；`/rea on` 后也要重启 |
| 3 | **首次 `/rea on` 后点一次"信任"** | 客户端安全机制，不能由脚本代点 | 「连接器管理 → 自定义连接器」里对 rea 点信任 |

另外：大文件下载（Node/JDK/JADX/Python）内置断点续传，网络中断后**重跑同一个脚本即可接着下**，不会重复下载。

## 二、装了什么（给你交个底）

### 1. 环境（全部绿色版，装到用户目录，不需要管理员权限）

| 组件 | 版本 | 作用 |
|---|---|---|
| Node | v24.22.3 | REA CLI 的运行环境 |
| JDK | Temurin 21（主版本固定） | Java 分析引擎依赖 |
| Python（安装器运行时） | 3.12.10 便携版 | 仅用于跑安装脚本，没有系统 Python 时自动下载，不进 PATH |
| REA CLI | `rea-agents` 6.10.1 | 204 条分析命令的命令行入口 |
| IDA 桥接 | ida-pro-mcp 2.0.0（内置离线包） | 把本机 IDA 接入 REA；**IDA Pro 本体需自备** |
| Android 依赖 | JADX 0.7.1（SHA-256 校验） | APK 反编译分析 |

### 2. 管理器 skill

`rea` —— 对话框输入 `/rea` 触发，负责装环境、查状态、按需开关、分析和留证（本页第四节全是它的命令）。装到 WorkBuddy、CodeBuddy、`~/.agents`（Codex / OpenCode 共用）。

### 3. 官方 skill

`reverse-engineer-anything` —— REA 官方说明书，描述各分析引擎与工具用法，自动生效，不用你手动导入。

### 4. 命令行

`rea` 命令 —— 终端里直接敲，例如 `rea --version`、`rea doctor`。默认零常驻时，所有分析都走这条 CLI 路径，不占上下文。

---

之前如果装过旧版的 `rea` 技能，会被这个新版**自动覆盖**：旧版移到 `~/.rea/skill-backups/`，不会留在技能目录里造成同名冲突。以前遗留的 `rea.bak-*` 目录也会被自动迁走，放心。

## 三、装完先验证一下（30 秒）

1. 新开一个终端，敲 `rea --version` —— 能出版本号。
2. 重启 WorkBuddy 后，对话框输入 `/rea status` —— 能看到环境状态清单。

两条都有输出 = 全部就绪。

## 四、日常使用

```
/rea 分析 D:/sample.exe        直接分析，不占用上下文、不用重启
/rea status                    看现在开没开、本机扫到哪些引擎
/rea on                        需要连续深挖同一个大文件时才开（要重启）
/rea off                       用完关掉，移除注册（自动备份）
/rea verify                    真跑一次分析，验证环境可用
/rea install                   环境坏了，重装（双击 cmd 的等价命令）
```

## 五、什么时候值得 `/rea on`

同一个文件连续追问第 3 次、单次分析超过 1 分钟、或文件 ≥ 20 MB。
只分析一次就 `off`，平时保持零常驻最省。

## 六、注意

- `on` / `off` 改的是配置文件，**必须重启客户端**才生效。
- 首次 `on` 后，若客户端看不到工具，去「连接器管理 → 自定义连接器」点一次**信任**。
- `IDA Pro` 本体是商业软件，需自备（安装器只负责把它接进来，不负责装它）。
- 分析时传给工具的必须是**原始二进制**（`.exe` / `.apk` 之类），不是 `.idb` / `.i64`。

## 七、常见问题

| 现象 | 解决 |
|---|---|
| `/rea` 敲了没反应 | 技能要重启客户端才出现；确认「技能」页里 `rea` 是启用状态 |
| 便携 Python 下载失败 | cmd 会换源重试（python.org → 华为云 → npmmirror）+ 断点续传；仍失败时按提示手动装 Python 再重跑 |
| 双击 cmd 一闪而过 | 右键"以管理员身份运行"不必要；先看是不是没解压直接双击 |
| 汇总里某项"失败" | 按日志提示重跑一次（下载类支持断点续传，不会重复下载） |
| `rea: command not found` | 重开终端（环境变量要刷新） |

详细说明见 `SKILL.md`，故障处理见 `references/troubleshooting.md`。
